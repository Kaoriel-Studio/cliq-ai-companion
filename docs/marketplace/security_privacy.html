Your Code, Your Control

Privacy is a core tenet of Cliq. We ensure your development environment stays secure:

Local Processing

The Cliq IDE Server runs exclusively on 127.0.0.1. It is not accessible from the external network. All communication between the IDE and your CLI agent happens locally on your machine.

Token-Based Authentication

Every time the IDE server starts, a unique, high-entropy security token is generated. The token is injected only into terminal sessions that Cliq itself starts for a configured agent — ordinary terminal tabs you open yourself never receive it. The token is also written to a discovery file created with owner-only permissions so other users on the machine cannot read it.

Changes Stay Inside Your Project

Cliq refuses to open a diff for, or write to, any path outside your project's content roots, and it refuses to modify files at all while the project is marked as untrusted. Attempts to escape the project directory (including via .. segments and symbolic links) are rejected and reported back to the agent as an error.

Prompts Go Only Where You Send Them

Cliq types prompts and @-context only into terminal tabs it started for an agent. If no agent session is running, Cliq tells you instead of typing into whatever tab happens to be selected. Templates that pull in your clipboard ask for confirmation first and show you exactly what will be inserted, and prompts built from clipboard content are never written to the prompt history.

No Hidden Tracking

Cliq does not send your source code to any external servers. Your code only goes to the CLI agent you have explicitly configured and launched. This includes diffs built for the Generate Commit Message action: the diff is only placed into the Cliq chat input, and is sent to an agent only when you explicitly choose to send it. Note that Cliq does not filter files by .gitignore — review what you attach as context before sending.

Code Review Host Access

GitHub and GitLab tokens are kept in the IDE password safe, one per configured host, and each token is sent only to the host it was configured for. Cliq asks before adding a host derived from a git remote and never follows HTTP redirects with a token; download links returned by GitHub for CI logs are fetched without any credentials. Requests are made only when you collect review context, and can bypass system and IDE proxies if you choose. Collected context never includes files that look like secrets (.env files, keys, certificates, credential stores), and text that looks like a token, private key or password literal is replaced with a [REDACTED] marker before it is written to disk.

Agent Secrets

Environment variables you configure for an agent (API keys and similar) are stored in the IDE's password safe rather than in plain-text settings, and are passed through the terminal session's environment instead of being prepended to the command line — so they never end up in your terminal scrollback or shell history.
